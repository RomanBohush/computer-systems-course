## Lab 1

**Представлення даних у пам'яті комп'ютера.** Код: `labs/lab01-data-representation/`.

### 1. Прогнози (записані до запуску)

- Розміри типів: char 1, short 2, int 4, long 8, long long 8, float 4, double 8, void * 8
- Бітове представлення -1 у int8_t: 11111111
- 255 + 1 у uint8_t: 0
- Порядок байтів 0x12345678 (A: 12 34 56 78 чи B: 78 56 34 12): Варіант B

### 2. Розміри типів (types.c)

```
char:      1 bytes
short:     2 bytes
int:       4 bytes
long:      8 bytes
long long: 8 bytes
float:     4 bytes
double:    8 bytes
void *:    8 bytes
```

| Тип | Байти | Біти |
|---|---|---|
| char | 1 | 8 |
| short | 2 | 16 |
| int | 4 | 32 |
| long | 8 | 64 |
| long long | 8 | 64 |
| float | 4 | 32 |
| double | 8 | 64 |
| void * | 8 | 64 |

- Чи всі типи займають однакову кількість пам'яті? Ні, розмір залежить від типу та платформи.
- Скільки бітів займає int? 32.
- Розмір void *? 8 байтів.
- Що це говорить про архітектуру? Вказівник зберігає адресу, тож 64-бітний вказівник означає 64-бітну архітектуру (x86-64) з 64-бітним адресним простором.

### 3. Decimal / Hexadecimal / Binary (representations.c, binary.c)

| Decimal | Hexadecimal | Binary |
|---|---|---|
| 10 | 0xA | 00001010 |
| 65 | 0x41 | 01000001 |
| 127 | 0x7F | 01111111 |
| 255 | 0xFF | 11111111 |
| 256 | 0x100 | 100000000 |
| 1024 | 0x400 | 10000000000 |

Вивід binary.c:

```
Decimal:   0  Hex: 0x00  Binary: 00000000
Decimal:   1  Hex: 0x01  Binary: 00000001
Decimal:  10  Hex: 0x0A  Binary: 00001010
Decimal:  65  Hex: 0x41  Binary: 01000001
Decimal: 127  Hex: 0x7F  Binary: 01111111
Decimal: 128  Hex: 0x80  Binary: 10000000
Decimal: 255  Hex: 0xFF  Binary: 11111111
```

Чому 65, 0x41 і 01000001 однакові? Це різні записи одного значення в системах числення з основами 10, 16 і 2. Комп'ютер зберігає лише біти, а десятковий та шістнадцятковий запис потрібні людині (64 + 1 = 65; 4*16 + 1 = 65).

Чому print_binary починає з біта 7? Біт 7 старший. Число записується зліва направо від старших розрядів до молодших, тому перевірку починають зі старшого біта, інакше число вивелося б задом наперед.

### 4. Символи (characters.c)

| Character | Decimal | Hex |
|---|---|---|
| A | 65 | 0x41 |
| B | 66 | 0x42 |
| a | 97 | 0x61 |
| 0 | 48 | 0x30 |
| 9 | 57 | 0x39 |

Що зберігається в `char c = 'A';`? Число 65 (байт 01000001). Літера A з'являється лише коли код інтерпретується за таблицею ASCII, наприклад при виводі через %c.

### 5. Signed та unsigned (signed_unsigned.c)

```
int8_t:  -1  hex: 0xFF
uint8_t: 255 hex: 0xFF
```

Очікуване представлення -1: 11111111 (двійковий додатковий код: 00000001 -> інверсія 11111110 -> +1 = 11111111).

Як 11111111 може бути і 255, і -1? Біти самі не мають значення. Як uint8_t усі 8 бітів значущі і виходить 255, як int8_t старший біт є знаковим і виходить -1. Значення визначається типом, тобто способом інтерпретації.

### 6. Межа unsigned (overflow.c)

Прогноз: 255 + 1 = 0.

```
value = 254
value = 255
value = 0
value = 1
```

Результат збігається з прогнозом: після 255 значення стає 0, потім 1. Число 255 це 11111111, максимум для 8 бітів. Сума 256 потребує 9 бітів (1 00000000), а змінна має лише 8, тож дев'ятий біт відкидається і лишається 00000000. Беззнакове значення обертається за модулем 256. Це стосується лише unsigned: для signed overflow у C поведінка не визначена, і переносити цей висновок не можна.

### 7. Байти в пам'яті та endianness (memory.c)

Прогноз: варіант B (78 56 34 12).

```
value = 0x12345678

Address             Value
0x7ffc2dc56cc8  0x78
0x7ffc2dc56cc9  0x56
0x7ffc2dc56cca  0x34
0x7ffc2dc56ccb  0x12
```

- У якому напрямку змінюються адреси? Зростають на 1 від p[0] до p[3].
- Який байт за найменшою адресою? 0x78, молодший байт.
- Чому це little-endian? Молодший байт лежить за меншою адресою, старший (0x12) за більшою. У big-endian було б навпаки.
- Чи змінилося число 0x12345678? Ні, значення те саме. Змінився лише порядок розташування його байтів у пам'яті.

### 8. Одні біти, різні інтерпретації

| Інтерпретація | Значення |
|---|---|
| Binary | 01000001 |
| Hexadecimal | 0x41 |
| Unsigned decimal | 65 |
| ASCII character | A |

Чому комп'ютеру недостатньо знати лише біти? Послідовність бітів не містить інформації про те, чим вона є. Значення визначається типом, інтерпретацією та контекстом: ті самі 01000001 можуть бути числом 65, літерою A, частиною машинної інструкції або кольором пікселя.

### 10. Відповіді на контрольні питання

1. Біт це найменша одиниця інформації (0 або 1). Байт це 8 бітів.
2. n бітів дають 2^n різних значень.
3. 8-бітне unsigned: 0...255.
4. 8-бітне signed у two's complement: -128...+127.
5. Hex зручний, бо одна hex-цифра відповідає точно 4 бітам, тож двійкові дані (адреси, байти, регістри) записуються коротко й читаються легко.
6. 11111111 як uint8_t це 255, як int8_t це -1. Біти однакові, відрізняється інтерпретація.
7. Після 255 + 1 у uint8_t значення стає 0 (обертання за модулем 256).
8. Для символу A в пам'яті зберігається один байт 01000001 (число 65, код ASCII).
9. Endianness це порядок розташування байтів багатобайтового значення в пам'яті.
10. Досліджувана x86-64 система використовує little-endian.
11. sizeof(int) це розмір типу int у байтах на поточній платформі (тут 4).
12. Одні й ті самі біти можуть бути різними даними, бо значення визначається типом та інтерпретацією, а не самими бітами.

### 11. Підсумок

Експериментально встановлено: на Linux x86-64 int займає 4 байти, long та вказівник по 8. Те саме значення можна записати в десятковій, шістнадцятковій та двійковій формах. Біти набувають значення лише через тип: байт 11111111 це 255 для uint8_t і -1 для int8_t. Беззнаковий uint8_t при 255 + 1 обертається в 0. Символи зберігаються як числові коди (A = 65). Система використовує little-endian: байти 0x12345678 лежать у пам'яті як 78 56 34 12 за зростаючими адресами.
